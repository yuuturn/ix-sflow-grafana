# 要件定義 / Todo — sFlow トラフィック可視化基盤

最終更新: 2026-10-19

## 1. 背景と目的

NEC UNIVERGE IX シリーズ (192.0.2.1) が出力する sFlow v5 を収集し、
Akvorado のスクリーンショットにあるような **Sankey 図** を含むダッシュボードで
トラフィックを可視化する。

Akvorado を動かせる VM がないため、同等の情報をより軽量な構成で再現する。

## 2. ゴール

| # | ゴール |
|---|--------|
| G1 | IX2207 の sFlow を継続的に収集し、PostgreSQL に蓄積する |
| G2 | Grafana で Sankey 図（送信元 → 宛先AS → サービス）を表示する |
| G3 | 送信元/宛先ランキング、時系列スループットも同一ダッシュボードで見る |
| G4 | IP → ASN を自動更新できる（商用ライセンスキー不要） |
| G5 | 再起動後も自動復旧し、データ保持期間を自動管理する |

## 3. 非ゴール（今回やらないこと）

- Akvorado そのものの導入（リソース要件が合わないため）
- フロー生データの全量保存（サンプリング統計として保存）
- BGP ピア情報・AS パス・インターフェース別の双方向分析
  （IX2207 の sFlow からは取得できない/今回不要）
- IPv6 の ASN 解決は実装済みだが、網羅性はデータソース依存

## 4. 機能要件

| ID | 要件 | 実装 |
|----|------|------|
| FR-1 | sFlow v5 を udp/6343 で受信 | sfacctd 1.7.8 (systemd) |
| FR-2 | サンプリングレートを考慮し実トラフィック量に換算 | `sfacctd_renormalize: true` |
| FR-3 | 5分バケットで集約し PostgreSQL に保存 | `sql_history: 5m` / `flows` テーブル |
| FR-4 | 内部/外部を判定し方向を付与 | `lan_prefix` テーブル（RFC1918 + LAN の IPv6 /64）で判定 |
| FR-5 | IP → ASN 変換（v4/v6） | `asn_range` + `ip_asn` 辞書 |
| FR-6 | Sankey 表示（SRC→DST(AS)→サービス） | Grafana + Plotly パネル |
| FR-7 | 期間・方向でフィルタ | 変数 `$direction`, `$topn` |
| FR-8 | ランキング表示 | 宛先/送信元/ポートのテーブルパネル |
| FR-9 | ASN データ自動更新 | systemd timer（週次） |
| FR-10 | 保持期間管理 | `prune_traffic()` + 日次 timer |
| FR-11 | MAP-E 環境で IPv4 を LAN ホスト単位に集計 | LAN `out` で NAPT 後の IPv4 を取得（`with-decapd` 時のみ `decapd` → `flows_decap`） |

## 5. 非機能要件

| ID | 要件 | 達成状況 |
|----|------|----------|
| NFR-1 | 既存サービスに影響を与えない | collector は空きメモリ 7GB / 負荷 0.2 |
| NFR-2 | ダッシュボードの応答が実用的 | Sankey 45〜80ms（ロールアップ使用時） |
| NFR-3 | 再起動後も自動起動 | systemd + `restart: unless-stopped` |
| NFR-4 | 認証情報を平文で晒さない | `.env` 0600、ロール分離 (pmacct/grafana) |
| NFR-5 | 最小権限 | pmacct=書き込みのみ、grafana=読み取りのみ |
| NFR-6 | 障害時に原因を追える | journald + `/var/log/pmacct/sfacctd.log` |

## 6. 前提・制約

- IX2207 は sFlow v5 エージェント機能を持つ（NEC 公式 FAQ に記載）
- コレクタはルータから到達可能な IP であること
- サンプリングのため値は統計的推定値（厳密値ではない）
- ライセンスキー不要の ASN データ（iptoasn.com）を使用

## 7. 構築先ホストの選定基準

本構成は小さく、**他のサービスと同居できる**ことを前提にしています。
実際に動かした環境（Raspberry Pi 4 8GB）での実測値を添えます。

| リソース | 実測（1Gbps 回線 / サンプリング 1:1000） | 推奨最低 |
|---------|------------------------------------------|---------|
| CPU | 負荷平均 0.3（4コア） | 2 vCPU |
| メモリ | 1.4 GB（pg 0.3 / grafana 0.2 / sfacctd 0.01 ほか） | 2 GB |
| ディスク | 13 GB（ASN データ 120 MB + 保持 45 日分） | 20 GB |
| アーキテクチャ | aarch64 で全コンポーネント動作 | amd64 / arm64 |

### 同居させる場合に確認すること

| 項目 | 理由 |
|------|------|
| TCP 3000（Grafana） | 競合するアプリがないか |
| TCP 5432（PostgreSQL） | 127.0.0.1 のみに公開しているので競合しにくいが、既存の PostgreSQL と混同しないこと |
| **UDP 6343（sFlow）** | sfacctd が占有する（`--with-decapd` 時は decapd）。他の sFlow コレクタと同居不可 |
| Docker が使えるか | 未導入なら `install.sh` の前に導入が必要 |
| sudo が使えるか | apt / systemd / /etc 配下の配置に必要 |

サンプリングレートにもよりますが、**1Gbps 回線なら Raspberry Pi 4 クラスで十分**です。
10Gbps を超えるような環境では、専用ホストか CPU の余裕があるマシンを推奨します。

## 8. ASN データソース選定

| 候補 | キー | 判断 |
|------|------|------|
| MaxMind GeoLite2-ASN | ライセンスキー必須 | 保留（乗り換え可能な作りにした） |
| **iptoasn.com** | 不要（パブリックドメイン） | ✅ 採用。v4+v6、722,604 レンジ |
| DB-IP Lite | 不要 | 代替候補 |

`scripts/update-asn.sh` の `download_data()` を差し替えれば MaxMind に移行できる。

## 10. 実機で判明した事項

構築中に判明し、設計に反映した内容。

| 事象 | 対応 |
|------|------|
| IX2207 の sFlow は `device`（物理IF）配下で設定する | 手順書を実機の構文に更新 |
| sFlow の方向は `sampling-rate` の第2引数（`in` / `out`）で指定。省略時は `in` | LAN `in`（アップロード）+ LAN `out`（ダウンロード）を有効化 |
| LAN の IPv6 がグローバルアドレスのため RFC1918 判定では外部扱い | `lan_prefix` テーブルで LAN の /64 を明示 |
| MAP-E の IPv4 は IPv6 カプセル化（proto 4）で内側が見えない | LAN `out` なら NAPT 後・デカプセル後の IPv4 が取れる。`out` 非対応機種は明示ラベルで表示し、誤った AS に紐づけない |
| iptoasn の列順が「AS, 国, 組織」だった（逆に実装していた） | ローダ修正、ASN 再投入 |
| `ip2num` の IPv6 変換で bigint オーバーフロー | numeric 演算に修正（Python と値一致を検証） |
| WAN `in` だけで採るとダウンロードの宛先が NAPT 前の公開アドレスになる | 既定を LAN `in`+`out` に変更。WAN 構成は `out` 非対応機種向けの任意機能に |
| MAP-E の内側 5-tuple は sFlow サンプルに含まれていた | `--with-decapd` 時に decapd で復元（フォールバック） |

## 11. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| IX2207 の CLI 構文が想定と違う | sFlow が飛ばない | 装置の `?` ヘルプ + コレクタ側 tcpdump で切り分け |
| サンプリングレート未申告 | 流量が 0/過小になる | `sfacctd_ext_sampling_rate` で強制指定 |
| ASN データが古くなる | 新規 AS が未解決 | 週次タイマー + `ip_asn` キャッシュ自動再構築 |
| ディスク肥大 | ディスク枯渇 | 日次 `prune_traffic()`（7日/45日） |
| SD カード寿命 | 装置故障 | 書き込みは 5分バケット + 60秒flush、`prune` で抑制 |
| 一時 sudo の残置 | セキュリティ低下 | 作業完了後に削除を依頼（上記 Todo） |
